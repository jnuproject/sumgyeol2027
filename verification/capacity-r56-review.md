# 한 캠퍼스 다인원 접속 · 모바일 화질 개선 r56

사용자가 2026-11-01 “응응 다 넣어봐”로 검토된 게임 전용 임시 상태/익명 RPC/자동 삭제 변경을 승인했습니다. 운영 migration campus_walk_shared_snapshots 적용 성공. 공개 배포용 릴리스입니다.

## 변경 내용

- 전원에게 위치를 방송하는 방식에서, 서버가 가까운 친구의 최신 상태를 한 번에 반환하는 방식으로 전환합니다.
- 인위적인 방/인스턴스 분리와 12명 제한을 없앴습니다. 모든 참여자는 같은 캠퍼스 좌표계를 사용하고, 150m 이내 참가자 상태를 인원수로 잘라내지 않고 반환합니다. 서로 가까이 이동하면 만날 수 있습니다.
- 화면에서도 기존의 16명/28명 표시 제한을 없앴습니다. 가까운 일부는 자세히 그리며 나머지는 간단한 바람방울을 한 번에 그립니다. 간단히 표시해도 각 참가자의 실제 위치·방향·이동은 유지됩니다. 거리, 시야, 건물 가림은 적용됩니다.
- 접속 표시는 최근 20초 내 공유 산책에 참여한 화면 수입니다. 임시 동시 입장 안전장치는 200명이며, 만원일 때에는 NPC 산책을 계속하고 15초 뒤 다시 확인합니다. 이는 200명 성능 보장 수치가 아닙니다.
- 클라이언트당 한 번의 위치 요청만 진행합니다. 기본 200ms 간격, 120명 초과 시 400ms 간격입니다. 오류 시 점점 느리게 재시도하며 전체방 방송으로 돌아가지 않습니다.
- 최근 두 위치로 최대 0.22초/3m까지만 예측합니다. 정지·오래된 표본·차단 지형을 처리하고, 실제 받은 위치로 부드럽게 보정합니다.
- 플레이어 바람방울 고정, 다섯 NPC, 대화·이동 구역 제한·채팅 금지는 유지합니다.

## 사용자 승인 후 적용한 운영 서버 변경

대상 프로젝트: vedraqrdkwyyipztxddw (jnuproject's Project)

1. 게임 전용 비공개 스키마 campus_walk_live와 sessions 표, 인덱스 추가. 기존 서비스 표는 변경하지 않습니다.
2. 공개 Data API 함수 public.campus_walk_sync(jsonb) 추가. 게임의 익명/로그인 클라이언트가 실행할 수 있습니다. 접근 대상은 이 게임의 임시 상태 표로 고정됩니다.
3. 함수는 SECURITY DEFINER로 실행하되 빈 search_path와 완전한 이름을 사용합니다. 표 직접 읽기는 허용하지 않으며, 각 접속의 무작위 UUID 비밀값으로 자기 상태 갱신/해제만 허용합니다. 전달받는 값과 반환 인원을 제한하고 채팅 등 추가 필드는 거절합니다.
4. cron 자동 정리 작업 campus_walk_expiry를 1분마다 실행합니다. 마지막 갱신 45초가 지난 정보를 삭제합니다. 정상 스케줄 기준 잔여 정보는 보통 105초 이내에 삭제됩니다. 접속 판정에서는 20초가 지나면 제외됩니다. 기록은 실제 GPS가 아닌 게임 안의 현재 좌표이며 이동 이력은 만들지 않습니다.
5. 실제 익명 API와 두 클라이언트 연결을 검증했습니다. 운영 DB 요청량과 전송량이 늘어나는 변경입니다. 요금제·지출 한도·접근 권한의 전역 설정은 바꾸지 않습니다.

## 확인한 범위와 한계

- 기존 기능 포함 125개 Node 검사 통과.
- 로컬 PostgreSQL(PGlite 0.5.14)에서 실제 SQL 실행: 같은 곳의 접속정보 100개가 나머지 99개를 모두 받고, 200개일 때 199개를 모두 받았습니다. 예전 격자 경계 반대편 참가자도 보입니다. 201번째 입장 안전장치, 만료 정리, 비밀값 보호, 익명 직접 읽기 차단, 채팅 필드 거절 검사 통과.
- 로컬 가상 군중 100개와 실제 브라우저 화면 1개를 같은 캠퍼스에 연결했습니다. 브라우저는 접속 101명/상대 상태 100개/상대 표시 100개를 보고했습니다. 데스크톱은 자세한 모델 28개 + 간단한 모델 72개, 390×844 모바일 화면은 16개 + 84개입니다. 간단한 모델은 참가자당 808개 삼각형을 사용하고 전체가 한 번에 그려집니다.
- 로컬 게임 화면과 별도 이동 클라이언트가 새 HTTP API로 서로 연결되어 접속 2명/상대 1명 표시를 확인했습니다. 로컬 관측 RTT 약 55ms. 이는 인터넷/휴대폰 지연 측정이 아닙니다.
- 로컬 SQL 검사는 단일 연결에서 순차 실행한 기능 검사이며, 가상 군중은 정적인 시험 정보입니다. 운영 100명/200명 동시 부하, 실제 모바일 회선 성능은 검증하지 않았습니다.


## 이번 운영 검증

- 실제 운영 익명 HTTP API에 테스트 참가자 2개 연결: 서로 보이며 접속 2명.
- 별도 test-UUID 범위에서 20개 HTTP 클라이언트를 동시에 짧게 실행: 300요청 성공, 각자 나머지 19명 확인. RTT 중앙값96ms/p95 346ms. 테스트 종료 시 자기 정보 해제. 이는200명 성능 보장이나 휴대폰 회선 측정이 아닙니다.
- cron campus_walk_expiry: 활성 및 실제 마지막 실행 succeeded 확인.
- anon은 private schema/table 직접 읽기 불가, 게임 RPC만 실행 가능 확인. 보안 advisor의 RLS정책 없음 및 익명 SECURITY DEFINER 실행 경고는 의도된 차단/공개 게임 API 설계에 해당합니다. UUID capability 검증·빈 search_path·입력/범위 제한 적용. 기존 다른 서비스 경고와 표는 변경하지 않았습니다.
- 모든125개 회귀 검사 통과.

## 모바일 선명도

기존 기본1배/최저0.75배로 일방 하락하던 렌더링을 기본 최대1.75배, 높음 최대2.25배로 변경했습니다. 기기 실제 DPR보다 높게 렌더링하지 않습니다. 균형 모드는 초기8초 이후 느린 상태8초에서만 단계적으로 낮추고,1.25배(저DPR 기기는 실제DPR)를 지키며 여유12초가 지속되면 복구합니다. 높음은 자동 축소하지 않습니다. 모바일 그림자는 정적1024/2048, 표면 비등방성8배. 선택한 화질은 브라우저에 저장됩니다.

390×844 브라우저 기본:1.75배,682×1477 실제 drawing buffer,1024 정적 그림자. 높음 선택 및 새로고침 후 유지:기기DPR2에서780×1688,2048 그림자. 실제 휴대폰 발열·FPS·배터리는 별도 현장 확인이 필요합니다.

사이트는 모두 같은 캠퍼스이며 12명 방 분리가 없습니다. 주변 참가자를 인원수로 숨기지 않지만, 거리에 따른 상태 전송과 상세도 조절은 있습니다. 임시 총 입장 보호200은 실제 최대 성능 보장이 아닙니다.
