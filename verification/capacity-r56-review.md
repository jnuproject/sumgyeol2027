# 다인원 접속 대비 수정안 — 운영 서버 적용 승인 대기

현재 공개 사이트는 npc-r55 그대로입니다. 이 수정안은 아직 GitHub main에 올리거나 운영 Supabase에 적용하지 않았습니다. 자동 승인 검토가 운영 스키마, SECURITY DEFINER 함수, 익명 실행 권한 및 cron 추가에 대한 명시적 승인이 필요하다고 거절했습니다. 로컬 DB 검증은 그 거절을 우회하는 운영 변경이 아닙니다.

## 변경 내용

- 전원에게 위치를 방송하는 방식에서, 서버가 가까운 친구의 최신 상태를 한 번에 반환하는 방식으로 전환합니다.
- 180m 격자와 20m 경계 여유를 사용합니다. 격자가 붐비면 방당 12명 이하로 자동 분산하고, 같은 방의 150m 이내 상대를 최대 11명 반환합니다. 다른 방/구역에 있는 친구는 서로 보이지 않을 수 있습니다.
- 접속 표시는 최근 20초 내 공유 산책에 참여한 화면 수입니다. 동시 입장 안전장치는 200명이며, 만원일 때에는 NPC 산책을 계속하고 15초 뒤 다시 확인합니다. 이는 200명 성능 보장 수치가 아닙니다.
- 클라이언트당 한 번의 위치 요청만 진행합니다. 기본 200ms 간격, 120명 초과 시 400ms 간격입니다. 오류 시 점점 느리게 재시도하며 전체방 방송으로 돌아가지 않습니다.
- 최근 두 위치로 최대 0.22초/3m까지만 예측합니다. 정지·오래된 표본·차단 지형을 처리하고, 실제 받은 위치로 부드럽게 보정합니다.
- 플레이어 바람방울 고정, 다섯 NPC, 대화·이동 구역 제한·채팅 금지는 유지합니다.

## 운영 서버에서 승인할 정확한 변경

대상 프로젝트: vedraqrdkwyyipztxddw (jnuproject's Project)

1. 게임 전용 비공개 스키마 campus_walk_live와 sessions 표, 인덱스 추가. 기존 서비스 표는 변경하지 않습니다.
2. 공개 Data API 함수 public.campus_walk_sync(jsonb) 추가. 게임의 익명/로그인 클라이언트가 실행할 수 있습니다. 접근 대상은 이 게임의 임시 상태 표로 고정됩니다.
3. 함수는 SECURITY DEFINER로 실행하되 빈 search_path와 완전한 이름을 사용합니다. 표 직접 읽기는 허용하지 않으며, 각 접속의 무작위 UUID 비밀값으로 자기 상태 갱신/해제만 허용합니다. 전달받는 값과 반환 인원을 제한하고 채팅 등 추가 필드는 거절합니다.
4. cron 자동 정리 작업 campus_walk_expiry를 1분마다 실행합니다. 마지막 갱신 45초가 지난 정보를 삭제합니다. 정상 스케줄 기준 잔여 정보는 보통 105초 이내에 삭제됩니다. 접속 판정에서는 20초가 지나면 제외됩니다. 기록은 실제 GPS가 아닌 게임 안의 현재 좌표이며 이동 이력은 만들지 않습니다.
5. 승인 후에는 실제 익명 API와 두 클라이언트 연결을 검증한 뒤 사이트를 배포합니다. 운영 DB 요청량과 전송량이 늘어나는 변경입니다. 요금제·지출 한도·접근 권한의 전역 설정은 바꾸지 않습니다.

SQL 원본: source-data/multiplayer/migrations/campus_walk_nearby.sql

## 확인한 범위와 한계

- 기존 기능 포함 122개 Node 검사 통과.
- 로컬 PostgreSQL(PGlite 0.5.14)에서 실제 SQL 실행: 접속정보 100개가 9개 방으로 배분, 방당 최대 12명, 응답 상대 최대 11명. 200개 입장 및 201번째 혼잡 처리, 만료 정리, 다른 비밀값의 갱신 차단, 익명 표 직접 읽기 차단, 채팅 필드 거절 확인.
- 로컬 게임 화면과 별도 이동 클라이언트가 새 HTTP API로 서로 연결되어 접속 2명/상대 1명 표시를 확인했습니다. 로컬 관측 RTT 약 55ms. 이는 인터넷/휴대폰 지연 측정이 아닙니다.
- 로컬 SQL 검사는 단일 연결에서 순차 실행한 기능 검사입니다. 운영 100명/200명 동시 부하, DB 잠금 경합, 실제 cron 실행, 실제 모바일 회선 성능은 검증하지 않았습니다. 운영 적용 승인이 있어야 다음 검증을 진행합니다.

## 이어서 작업할 때

이 수정안은 /tmp/jeju-multiplayer-r49의 로컬 작업입니다. 운영 적용 승인을 받기 전에는 SQL을 실행하거나 이 분기를 GitHub main으로 올리지 않습니다. 로컬 프로젝트 verification/capacity-r56-draft/에 패치와 SQL, 검토 문서를 별도로 보존합니다. 현재 운영 배포 기록 GITHUB.md는 npc-r55를 유지합니다.

PGlite 의존성은 source-data/multiplayer/capacity-validation의 잠금 파일로 고정되어 있고 사이트 런타임에 포함되지 않습니다. 검사는 PGLITE_MODULE로 설치된 dist/index.js 경로를 지정하여 verification/capacity-local.mjs를 실행합니다. 로컬 미리보기 서버도 운영 Supabase에 연결하지 않습니다.
